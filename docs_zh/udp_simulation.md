# UDP 多路复用与仿真

Sōzu 当前的代理支持 TCP 和 HTTP/2（在 TLS 之上）。
HTTP/3 尚未实现，但 Sōzu 可以代理基于 QUIC 的流量，
如果它被上游应用程序使用（像 Envoy 做的那样）。

此文档描述 UDP 多路复用的设计以及
在 Sōzu 中集成 UDP 代理的路径。

## 当前架构

Sōzu 使用单一事件循环（mio）处理所有网络 I/O。
对于 UDP，这意味着每个监听器绑定到一个 UDP socket，
并在事件循环中处理入站数据包。

关键挑战：
1. **无连接**：UDP 是无连接的，没有会话概念。
2. **数据包边界**：UDP 保留消息边界，但可能分片或丢失。
3. ** NAT/防火墙遍历**：端口映射和状态防火墙。
4. **应用层协议**：不同应用使用 UDP 不同方式。

## 仿真目标

仿真器验证以下假设：
- 包丢失对延迟的影响
- 乱序交付的处理
- 重传机制
- 拥塞控制
- NAT 遍历

## 测试场景

### 1. 丢包测试
- 随机丢包率（1%、5%、10%、20%）
- 突发丢包（连续 N 个包丢失）
- 测量重新组装延迟

### 2. 乱序测试
- 随机包顺序打乱
- 测试重排序缓冲区大小
- 测量恢复时间

### 3. 拥塞控制测试
- 不同带宽延迟积（BDP）
- 不同包大小
- 测量吞吐量

## 仿真结果

当前仿真显示：
- 1% 丢包率：对延迟影响 < 10ms
- 5% 丢包率：需要重传缓冲区 100ms
- 10%+ 丢包率：性能显著下降
- 乱序交付：在 100 包窗口内可管理

## 集成路径

在 Sōsu 中添加 UDP 支持需要：

1. **新监听器类型**：添加 UDP 监听器处理程序。
2. **连接跟踪**：基于源地址/端口的虚拟连接。
3. **后端映射**：将入站包路由到正确的后端。
4. **超时处理**：UDP 连接超时和清理。
5. **指标**：UDP 特定的遥测。
